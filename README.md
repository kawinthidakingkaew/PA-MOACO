# ระบบจัดการเส้นทางการท่องเที่ยว จังหวัดภูเก็ต — Frontend

เว็บแอปวางแผนเส้นทางท่องเที่ยวภูเก็ตตามงานวิจัย PA-MOACO สร้างด้วย React 18 + Vite + TypeScript
หน้าตาและคอมโพเนนต์ทั้งหมดมาจาก Design System ของโปรเจกต์ (token และ class `ar-*` เดียวกัน)

## เริ่มใช้งาน

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # ทดสอบสูตรค่าใช้จ่าย การจัดเส้นทาง และสถานะแผน (Node 22.6+)
npm run build      # ตรวจชนิดด้วย tsc แล้ว build ไปที่ dist/
```

คัดลอก `.env.example` เป็น `.env` เมื่อต้องการต่อ backend หรือ Google จริง ถ้าไม่ตั้งค่า แอปจะทำงานด้วยข้อมูลจำลองในเบราว์เซอร์ทั้งหมด

## ขั้นตอนของผู้ใช้

| หน้า | เส้นทาง | อ้างอิง |
|---|---|---|
| 1 เลือกโปรไฟล์ (11 โปรไฟล์ พร้อมแผนที่และภาพ) | `#` | FR-01–03, UC-01 |
| 2 จัดเส้นทาง: จุดเริ่มต้น (ค้นหา ปักหมุด ตำแหน่งปัจจุบัน) รัศมี วัน คน งบ แล้วเพิ่ม ลบ สลับลำดับรายวัน | `#plan` | FR-04–20, UC-02–05 |
| 3 สรุปทริป: ระยะทาง เวลา ค่าใช้จ่าย งบ ตารางรายวัน | `#summary` | FR-21–25, UC-06 |
| ทริปของฉัน: ค้นหา กรอง 30 วัน เปิด PDF อีเมล เปลี่ยนชื่อ ทำสำเนา ลบ | `#trips` | FR-27, UC-20 |

**ผู้ใช้ทั่วไป** วางแผนและดูสรุปได้ครบ ปุ่มบันทึก ส่งอีเมล และพิมพ์/PDF ยังกดได้ แต่มีไอคอนกุญแจ กดแล้วเปิดหน้าต่างเข้าสู่ระบบด้วย Google
หลังเข้าสู่ระบบ แอปทำคำสั่งเดิมต่อทันที แผนเก็บใน `sessionStorage` จึงไม่หาย (FR-26, FR-36, UC-07a)

**ค่าใช้จ่าย** = ค่าเดินทาง 10 ฿/กม. ตามระยะถนน + ค่าเข้าชม × จำนวนคน + ค่าไกด์เหมาจ่าย 500 ฿ ต่อทริป (`src/domain/config.ts`)

## โครงสร้าง

```
src/
  domain/      ชนิดข้อมูล ค่าคงที่ สูตรค่าใช้จ่าย การจัดเส้นทาง สถานะแผน (ไม่มี React ทดสอบได้ด้วย node)
  data/        โปรไฟล์ 11 แบบ สถานที่ตัวอย่าง 93 แห่ง จุดเริ่มต้น รูปร่างเกาะ
  i18n/        ข้อความไทย/อังกฤษ และ useT()
  components/  คอมโพเนนต์จาก Design System (Button, MiniMap, StopList, CostTable, LoginDialog, …)
  pages/       หน้าจอทั้ง 4 หน้า
  state/       ภาษา ธีม ผู้ใช้ แผนทริป toast ประตูเข้าสู่ระบบ และ router แบบ hash
  services/    api.ts (mock + สัญญา REST), auth.ts (mock + โครง Google)
  styles/      tokens.css, components.css (จาก Design System), app.css (ส่วนเสริมระดับแอปและหน้าพิมพ์)
tests/         node:test
```

## สิ่งที่ต้องต่อของจริง

1. **PA-MOACO**: `services/api.ts` → `POST /plan` คืน `{ plan: string[][] }` ตอนนี้ใช้ `domain/planner.ts` ซึ่งเป็น greedy ตัวแทนชั่วคราว
2. **Google Sign-In**: `services/auth.ts` มีขั้นตอนและ `httpAuth` ให้แล้ว ต้องทำ `getCode()` ด้วย Google Identity Services และใช้ปุ่มทางการตามแนวทางแบรนด์ของ Google (ตัว "G" ในเดโมเป็นตัวแทน)
3. **Backend ทริปและอีเมล**: `httpApi()` กำหนดเส้นทาง `/trips`, `/trips/:id`, `/trips/:id/duplicate`, `/trips/email` ตามเอกสารออกแบบฐานข้อมูล (soft delete, email_log, จำกัดจำนวนครั้ง) ยังไม่ได้ทดสอบกับเซิร์ฟเวอร์
4. **PDF**: เดโมใช้หน้าพิมพ์ของเบราว์เซอร์ (`@media print`, A4) ผู้ใช้เลือก "บันทึกเป็น PDF" ถ้าต้องการไฟล์ PDF จาก server ให้เพิ่ม endpoint แล้วเปลี่ยน `onDownload`
5. **แผนที่**: `MiniMap` เป็น SVG ไม่ต้องโหลด tile ถ้าจะใช้ MapLibre GL + OpenFreeMap ให้คง props ชุดเดิม
6. **ภาพสถานที่**: `PlaceImage` รับ `src` ได้ ตอนนี้วาดภาพแทนจากสีโปรไฟล์
7. **ระยะถนน**: ตอนนี้ = ระยะเส้นตรง × 1.41 ควรใช้ระยะจาก routing engine (เช่น OSRM)
